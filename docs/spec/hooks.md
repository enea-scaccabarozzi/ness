# Hooks (HOOK)

cli `hook` (machinery). Sources: §4 (shadowing at session-start), §5 (`ness hook`), §6 (hook
wiring and wrapping), §13 (polling guard, cheat sheet), migration F6 (waiting rule, cheat sheet),
P4 (adopted root after compaction), D14.

## Wiring

- **R-HOOK-001** Client hook entries generated by sync MUST invoke `ness hook <EVENT>` wrapped so
  that a checkout without ness on `PATH` sees exit 0 and no output (R-SYNC-054).
  Verify: testscript — run the wired command with PATH lacking ness → exit 0, empty output.
- **R-HOOK-002** `ness hook EVENT` invoked by a client session that is not bound to a ness session
  (no `NESS_SESSION`, no adopted conversation) MUST print nothing and exit 0 — including when the
  payload does not parse, and with no shadowing check — except for the note of R-HOOK-019.
  Verify: testscript — no session env; `session-start`, `pre-tool` with benign, blocked-looking
  and garbage payloads → empty stdout, exit 0.

## `session-start`

- **R-HOOK-019** `session-start` in a ness project for a conversation that is not a ness session
  MUST print the unbound note telling the agent how to promote the conversation to a root
  (R-SESS-038), write no ready mark and touch no store row; outside a ness project, or when the
  project does not load, it MUST stay silent.
  Verify: testscript — no session env in an initialized repo: stdout equals the note, no session
  row; plain git repo: empty; pre-tool unbound: empty.
- **R-HOOK-003** `ness hook session-start` MUST write the ready mark the launch waits for
  (R-SESS-032).
  Verify: testscript — launch in phase waiting-ready; after the hook the store shows ready.
- **R-HOOK-004** `session-start` MUST print the session's identity (id, scope, manager) and phase
  for the client to load as context.
  Verify: testscript — stdout contains the id, scope and manager id.
- **R-HOOK-005** For a bound session, `session-start` MUST run the shadowing check
  (R-SESS-005/006) and, on an exact match, block the session naming both paths.
  Verify: contract(fake+real) — global skill shadowing a project skill; the client receives the
  blocking response naming both paths.
- **R-HOOK-006** At every start of a bound session (startup, resume, clear, compact),
  `session-start` MUST print a cheat sheet of at most 20 lines containing one-line forms of
  `open`, `inbox`, `send`, `reply`, `integrate`, `close` and `probe`; after a compaction
  (`source = compact`) it also says to re-read the brief and the inbox. (Amended after field run
  1: sessions that only saw it after compaction re-read `--help` for every command.)
  Verify: testscript — startup and compact payloads → stdout ≤ 20 lines containing each
  command; golden files; the re-read line only after compaction.
- **R-HOOK-007** After compaction, `session-start` MUST print the files listed in the
  `ness-entry#post-compact` list slot for reload (§16 #9).
  Core's own reload lines (R-BLT-107) print before the profile's.
  Verify: testscript — a profile appends a path to the slot; it appears in the compact output,
  after core's two lines.
- **R-HOOK-008** For a root adopted with `open --root --here`, `session-start` after compaction
  MUST keep its identity and MUST NOT tell it not to attach the running conversation (P4
  regression).
  Verify: testscript — adopted root, compact payload → output contains its id, not the
  "do not attach" text.
- **R-HOOK-009** `session-start` MUST NOT write the ready mark twice for one launch or change the
  phase of a session that is already running.
  Verify: testscript — second startup payload → phase unchanged.

## `pre-tool`

- **R-HOOK-010** `ness hook pre-tool` MUST run the contract guard (contracts.md, R-CTR-009..012)
  when the `contracts` feature is enabled.
  Verify: testscript — see contracts.md.
- **R-HOOK-011** For a bound session, `pre-tool` MUST refuse Monitor, ScheduleWakeup and CronCreate
  calls, and Bash wait loops, whose command includes `ness inbox` or `ness status`, with a
  message stating the waiting rule. A wait loop is one that can run without end: `while`,
  `until`, `for ((`, `watch`, and any loop with a `sleep` in it. A `for NAME in WORDS` loop
  without a sleep is a finite read and MUST pass (`for i in m-a m-b; do ness inbox --show $i;
  done`). The Bash message MUST also point at `ness inbox --show A B C` and `ness inbox --unread`.
  (Field round 3: all 54 refusals in a week were finite reads after a wake.)
  Verify: testscript — payloads for each tool and loop form with each command → blocked; message
  contains "end your turn"; the same tools without those commands → allowed; unit
  `waiting_test` — the field's `for` reads allowed, wait loops blocked with the `--show`/`--unread`
  pointer.
- **R-HOOK-012** `pre-tool` MUST allow a single `ness inbox` call.
  Verify: testscript — Bash `ness inbox` → allowed, no output.
- **R-HOOK-013** For a bound session, `pre-tool` MUST run the output guard: refuse a whole-file read
  (Read without offset/limit, `cat`/`sed` of the whole file) of a saved tool-result file.
  Verify: testscript — Read of a saved tool-result path without range → blocked; with
  offset/limit → allowed; `cat` of it → blocked.
- **R-HOOK-020** For a bound session, `pre-tool` MUST refuse a Bash command that backgrounds work
  with an unquoted lone `&` (`( ... ) &`, a trailing `&`, `cmd & next`), unless the call sets
  `run_in_background: true`. `&&`, `&>`, `>&`, `<&`, `|&`, `2>&1`, an `&` inside quotes, a here-doc
  body (also one started inside `$( )` inside double quotes, as in `git commit -m "$(cat <<'EOF'
  ...)"`), `$(( ... ))` arithmetic, `${ ... }`, a comment, and an `&` whose next command on the line
  is `wait` MUST pass. The message says nothing wakes the session when the job ends and
  points to `run_in_background`. (Field run the research lab: a commit backgrounded with `( ... ) &`
  left a session dead 4.8 h.)
  Verify: unit — blocked and allowed tables; testscript — exit 2 with the message on stderr.
- **R-HOOK-021** For a bound session, `pre-tool` MUST refuse a Bash wait loop (R-HOOK-011) whose
  command runs `pgrep` with `-f` (any flag cluster containing `f`, also after other flags such as
  `-u me -f`) or `--full`: the pattern matches the
  loop's own command line, so the wait never ends. The message points to `run_in_background`.
  (Field run the research lab: 8.7 h dead.) A one-shot `pgrep -af PATTERN`, one in a `for` over its
  output, and one beside a loop it is not inside MUST pass: they are lookups, not waits.
  Verify: unit and testscript, as R-HOOK-020.
- **R-HOOK-022** For a bound session, `pre-tool` MUST run the project guards after the built-in
  guards (`hook.PreTool`, the contract guard keeps its place): the default guards (R-HOOK-023,
  R-HOOK-024), then the `[[guards]]` of `.ness/ness.toml` in file order. A guard applies when its
  `tool` matches the tool name and its `match` matches the Bash command, or any file path the call
  edits (`file_path` of Edit, Write, MultiEdit); with `content`, the new text of the call
  (`new_string`, `content`, `edits[].new_string`; never `old_string`) must match too. The first
  guard that applies refuses with exit 2 and `message` followed by its pointer on stderr
  (R-HOOK-014); none applies: silent. An unbound session is never guarded.
  Verify: unit — configured Bash guard blocked/allowed rows, a content guard that ignores
  `old_string`; testscript — exit 2 with message and pointer, unbound silent.
- **R-HOOK-023** The default gate guard MUST refuse a Bash command that runs the configured `gate`
  (at the start of the command or after `&&`, `||`, `;`, `|`, a newline, ending at a word
  boundary), so `make validate`, `cd x && make validate` and `make validate; echo` are refused
  while `make validate-docs` and `go test ./internal/hook` are not. With an empty `gate` there is
  no gate guard. Pointer ness-entry, section Tests.
  Verify: unit — the blocked and allowed rows above; testscript — exit 2 naming the gate.
- **R-HOOK-024** The default launch-limits guard MUST refuse an edit of `.ness/ness.toml` whose new
  text mentions `max_children` or a `[launch`, `[tiers` or `[worker` table, and MUST NOT refuse an
  edit of another file, an edit of another key of that file, or an edit that mentions them only in
  `old_string`. The message says limits are the operator's to change. Pointer ness-launch, section
  Child or subagent.
  Verify: unit — Edit, Write and the second edit of a MultiEdit blocked; the three allowed rows.
- **R-HOOK-025** For a bound session, `pre-tool` MUST refuse a Bash loop (`while`, `until`, `for`)
  that sleeps around `ness integrate`, `ness send` or `ness open`, with a message ending in
  `(skill ness-entry, section Communicate)`: a retry is not a wait, so the session ends its turn
  and the worker wakes it. A plain `ness integrate`, and a loop that runs `ness integrate` per
  branch without sleeping, MUST pass. Every loop guard (this one, R-HOOK-011, R-HOOK-021) MUST
  require the ness call inside the loop (its condition or body): a loop and a `ness status` that
  share a command line but not a loop, as in `for b in a b; do git log $b; done; ness status`,
  MUST pass. (Field run: the installed hook refused exactly that command as a shell loop over
  `ness status`.) A loop is closed only by a `done` in command position, so a loop that prints
  the word (`echo done`, `echo "done"`, `printf 'all done'`) is still a loop and MUST be refused;
  and the scan MUST ignore here-doc bodies and quoted strings handed to a command other than a
  shell (`git commit -m "... while ... sleep ... ness integrate"`, `cat <<EOF ... EOF`), which are
  prose; a script handed to another interpreter (`python3 -c "..."`, `node -e '...'`) is not shell
  either. A quoted script given to a shell's `-c` (`bash -c`, `sh -lc`, `zsh -c`) is code and is
  still scanned.
  Verify: unit `waiting_test` — blocked and allowed tables, the `for` and `while` forms of the
  shared-line case among them; unit `review_test` — loops that print "done" blocked, here-doc and
  quoted prose allowed; testscript `hook_pretool_explore`.
- **R-HOOK-026** For a bound session, `pre-tool` MUST refuse a subagent call (tool `Agent`, or the
  legacy `Task`) whose `subagent_type` is `Explore`, with a message naming `ness-sweep` and ending
  in `(skill ness-entry, section Communicate)`: Explore runs on the main model. Any other
  `subagent_type`, and another tool carrying that field, MUST pass.
  Verify: unit `waiting_test` over a recorded payload (`internal/hook/testdata/agent_explore.json`);
  testscript `hook_pretool_explore`.
- **R-HOOK-027** The session-start identity line MUST carry the root's size (`size quick`) between
  the manager and the phase, and omit it for a child. The unbound note MUST list the project's sizes in the promote command (`--size quick|full`, plus
  each profile size) and name the default when a profile adds one, and say `ness size` changes it later.
  Verify: testscripts `size_cmd`, `open_here`, `hook_unbound_note`, `size_hook_note`.
- **R-HOOK-030** The rung verdict MUST be: below the recommendation `below`; at it `allowed`; one
  rung above with an escalate reason `escalated`; anything higher, or one above without a reason,
  `refused` (refuses) under `models.enforce = "refuse"` and `would-refuse` (allows) under `"log"`.
  Verify: unit `spawn_test` — the full table.
- **R-HOOK-031** A subagent call (tool `Agent`, or the legacy `Task`) MUST be read as its
  `subagent_type`, `model`, `effort` and the prompt lines `kind: <name>` and `escalate: <reason>`,
  read only from the prompt's leading header (consecutive non-empty `key: value` lines; the first
  other line ends it), matched after spaces, key case-insensitive, kind lowercased, `sweep` read as
  `search`; an empty reason is no
  escalate; a non-object input is a call declaring nothing; any other tool is not a call.
  Verify: unit `spawn_test`.
- **R-HOOK-032** Reading a subagent call MUST never panic on any payload.
  Verify: fuzz `FuzzParse`.
- **R-HOOK-033** Every judged subagent call (allowed, below, escalated, refused for any cause,
  would-refuse, fork) MUST be stored with session, agent type, kind, requested and recommended
  rung, verdict, reason and time; an Explore refusal is not judged. A failed store write MUST be
  reported on stderr and never change the verdict.
  Verify: unit `store/spawns_test` (round trip, order, filter, migration 11); unit
  `cli/hook_spawn_test` (closed store).
- **R-HOOK-034** For a bound session the requested rung MUST be the call's `model` and `effort`
  found on the ladder, or, with neither, a named ness agent's rendered rung; a `model` without an
  `effort` MUST take the effort of the rung the prompt's kind (else the named agent's kind) maps to
  when that rung has the model, and is then judged as that rung. Otherwise a pair off the ladder
  (a full model id included), a half pair, or an unnamed agent without a pair MUST be refused with
  the ladder (`name model/effort` per rung) and a pointer to `ness pick`.
  Verify: testscript `hook_pretool_spawn`; unit `cli/hook_spawn_test` (model without effort).
- **R-HOOK-035** The recommended rung MUST be the configured selector's for role subagent, the
  prompt's kind or the named agent's; a selector failure (a timeout included) MUST judge against
  base within the selector's timeout; a missing kind MUST be refused listing the kinds. A refusal
  MUST name the requested rung, the recommended rung with model/effort, the selector's reason,
  both ways out (lower the rung, or `escalate: <reason>`) and end in
  `(skill ness-entry, section Model and effort)`.
  Verify: testscript `hook_pretool_spawn`; unit `cli/hook_spawn_test` (hung command selector).
- **R-HOOK-036** An escalate MUST buy exactly one rung, and a refusal of an escalated call MUST say
  so; a `fork` subagent MUST be allowed with verdict `fork`; the legacy `Task` tool is judged the
  same.
  Verify: testscript `hook_pretool_spawn`.
- **R-HOOK-037** An unbound client MUST never have a subagent call judged or stored.
  Verify: testscript `hook_pretool_spawn`.
- **R-HOOK-014** A refusal from `pre-tool` MUST exit 2 with the reason on stderr (the client's
  blocking mechanism) so the tool call does not run.
  Verify: contract(fake+real) — exit code 2 and reason; real Claude Code session: blocked Edit
  leaves the file unchanged.
- **R-HOOK-017** For a bound session, a `pre-tool` payload that does not parse MUST be refused
  (exit 2 with a reason).
  Verify: testscript — garbage payload with `NESS_SESSION` set → exit 2.
- **R-HOOK-018** For Codex, the launch MUST wire `session-start` and `pre-tool` with `-c`
  overrides on the codex command line.
  Verify: contract(fake) — codex argv contains `-c` entries running `ness hook session-start` and
  `ness hook pre-tool`.
- **R-HOOK-015** The hook-payload parser MUST NOT panic on any input.
  Verify: fuzz — arbitrary stdin payloads for both events.
- **R-HOOK-016** `ness hook` with an unknown EVENT MUST exit 0 silently (fail open: an older binary meeting a newer profile must not block the
  client).
  Verify: testscript.
